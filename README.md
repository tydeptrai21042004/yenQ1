# IWT–Schur 4×4 watermarking: reproducible experiment suite

One **proposed blind keyed IWT–Schur method**, 16 original literature-baseline implementations, and an audited experiment protocol. The source package does **not** contain claimed experimental results; all CSVs and figures are generated by executing the code. All baseline implementation sources are checked against their original SHA-256 manifest.

## Reproduce from GitHub on Ubuntu / WSL

```bash
git clone https://github.com/tydeptrai21042004/yenQ1.git
cd yenQ1
bash scripts/run_all_ubuntu.sh full
```

This installs dependencies in `.venv`, runs regression tests, and executes the full paper protocol (including all baselines, all selected ablations, sweeps, security controls, comparisons, audits, and figures). **First push the files from this updated package to GitHub**; the old GitHub checkout does not yet contain these updates.

For an inexpensive smoke check, **not a paper result**:

```bash
bash scripts/run_all_ubuntu.sh quick
```

If the environment is already installed:

```bash
source .venv/bin/activate
export OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1
python scripts/run_paper_protocol.py --profile full --include-baselines --fail-fast
```

Re-running the same command resumes successfully completed stages. Within long stages, complete method/variant/host/watermark groups are restored only when **the exact same configuration, source inputs, implementation code, protocol hash, and attack limit** match. Use `--force` on the paper runner to re-execute stages or `--fresh` on individual experiments to ignore existing rows. Use `--dry-run` to inspect the full plan without running it.

Ubuntu packages (if venv is unavailable): `sudo apt install python3-venv python3-pip`. Python 3.10+ is required. PyWavelets, Pillow's JPEG2000 and WebP codecs, and NumPy/SciPy are installed or checked through the scripts. Running all methods on all 16 held-out host/watermark pairs can be computationally expensive; there is **no claim that the full study has already been executed**.

## Single canonical attack protocol

**Exactly 61 evaluation conditions per comparable method × variant × host × watermark:** one clean image (`C000`) followed by `A001`–`A060`, comprising 20 named attacks at Mild, Moderate and Strong levels. Five categories:

| Category | Four attacks × three severities |
| --- | --- |
| Compression | JPEG, JPEG2000, bit depth, lossy WebP |
| Noise | Gaussian, salt-and-pepper, speckle, Poisson |
| Filtering | Median, average, Gaussian blur, sharpening |
| Geometry | Rotation, resizing, centered crop, translation |
| Photometric | Brightness, contrast, gamma, saturation |

The executable definitions and numeric parameters live **only** in `src/qr64_certified/proposed/iwt_schur_v7/attacks.py`. Every benchmark, ablation, baseline, QIM sweep, and payload sweep calls that same attack function with the same seed, case ID, and protocol checksum. `outputs/paper_protocol/attack_definitions/attack_definitions.csv` enumerates all **61 conditions**. The three-attack quick profile generates only `C000,A001,A002,A003` and is explicitly labelled as a partial smoke test. No results are fabricated for missing cases.

The protocol uses **WebP lossy compression instead of color quantization**; it must not be described as identical to an older 60-attack suite that used color quantization. JPEG2000's parameters are Pillow `quality_mode='rates'` settings, not quality factors. Attacks normalize outputs to 512×512 BGR `uint8`, including crop+resize and downscale+upscale definitions.

Security controls (wrong key, wrong nonce, unmarked host, unrelated host) and Schur coefficient-energy analysis are **separate experiments**, not 61 image-attack conditions. They are not represented as such.

## Research split and scheduled experiments

- **Development:** `Girl`, `house`, `pepper`, `sailboat`, with watermark `wm.png`. QIM strength and repetition sweeps run here; parameters are not tuned on held-out images.
- **Held-out evaluation:** `airplane`, `athens`, `baboon`, `butfly`, `manhatan`, `milkdrop`, `safari`, `tiffany`, with both `wm.png` and `Cc.logo.circle.png` (16 image-watermark pairs).
- **Proposed benchmark:** 16 × 61 = **976** result rows.
- **Ablations:** 7 decoder and 6 encoder settings, 16 × 13 × 61 = **12,688** rows. Decoder-only variants use the same attacked image; encoder variants require re-embedding.
- **Baseline attempts:** 16 registered methods × 16 × 61 = **15,616** rows/condition records. **DEW Langelaar (2001) has a native capacity of 2,048 bits on these hosts and cannot carry the fixed 4,096-bit watermark.** Its 61 rows per pair are explicitly marked `not_applicable_capacity`, not evaluated as zero robustness. The remaining **15 baseline engines** are eligible for numerical comparisons, subject to successful execution.
- **Development QIM sweep:** 4 × 9 × 61 = **2,196** rows. **Development copy/repetition sweep:** 4 × 6 × 61 = **1,464** rows.
- **Security and energy:** separate outputs; baseline paper/provenance audit also generated.

Primary blind comparisons should be distinguished from semi-blind, non-blind, and heavily adapted published-method implementations. Consult `configs/paper_baseline_provenance.json`, `configs/baseline_parameters.json` and `outputs/paper_protocol/baseline_audit/` before claiming paper-to-paper equivalence. Keeping a published algorithm's source unchanged does not make its image/payload adapters mathematically identical to the original paper.

| `outputs/paper_protocol/reports/security_summary.csv` | Unmarked/wrong-key false accept counts |
| `outputs/paper_protocol/reports/mean_attacked_nc.pdf` | Comparison figure (also PNG) |
| `outputs/paper_protocol/*/per_attack.csv` | Raw per-condition results for every experiment |

All rows embed `condition_id`, `protocol_version`, and `protocol_sha256`, allowing an auditor to reject duplicate, missing, mismatched or failed conditions. A clean image has its own observed NC/BER and PSNR/SSIM. **Detection failure remains a failure even when the extracted watermark achieves a high NC**; baselines that do not provide detectors have no fabricated detection status. An NC of 0.85 is a reporting threshold, **not** a success guarantee or the definition of protocol completion.

```bash
python scripts/reproduce_v7_reference.py --out outputs/v7_exact_reference
python scripts/reproduce_v7_reference.py --out outputs/v7_exact_reference \
    --reference /path/to/FINAL_IWT_Schur_4x4_V7_WebP_60_Attacks.csv
```

This reference configuration uses key `FIXED_T44_DEMO_KEY`, nonce `pepper_wm_fixed_t44`, seed `2026`, eight iterations, and LL/detail/pilot QIM steps `28/14/32`. The example keys are public, **not deployment secrets**. Use of a different nonce/key changes actual embedding and results.

## Method outline

The proposal applies integer Haar IWT independently to B/G/R; splits LL/LH/HL/HH into 4×4 blocks; modifies a single eigen/real-Schur diagonal coordinate (`LL/HH=T44`, `LH/HL=T11`); adds keyed dispersed repetitions and separate geometry/QIM-phase pilots; and extracts blindly with optional geometric, photometric, denoising and structural recovery. The binary watermark is embedded directly, not transformed.

This is experimental research software; there is no certified robustness or security guarantee. The experiment runner and audit do not modify the 16 baseline source implementations.
